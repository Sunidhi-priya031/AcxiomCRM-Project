# AcxiomCRM

A role-based CRM web application covering the customer–sales lifecycle: lead capture and qualification, conversion to
customers and opportunities, follow-ups, activities, sales pipeline, dashboard analytics, reports, REST API and an
append-only audit log. Built to the *AcxiomCRM Complete Project Assignment* specification.

**Stack:** ASP.NET Core 8 MVC (C#) · ASP.NET Core Identity · Entity Framework Core 8 + SQLite · Razor views with
unobtrusive validation · Bootstrap 5.3 · Bootstrap Icons · Chart.js 4. All front-end libraries are bundled in `wwwroot/lib`
(the app works offline).

---

## 1. Run it locally

**Prerequisite:** [.NET 8 SDK](https://dotnet.microsoft.com/download/dotnet/8.0). No database server is needed – SQLite
creates `src/AcxiomCRM/App_Data/acxiomcrm.db`.

```powershell
# Windows (PowerShell), from the repository root
.\setup.ps1                  # restores packages, stores the demo password in user-secrets,
                             # generates the InitialCreate migration and creates the database
dotnet run --project src/AcxiomCRM
```

```bash
# macOS / Linux
./setup.sh
dotnet run --project src/AcxiomCRM
```

Open **http://localhost:5173**. In Visual Studio, open `AcxiomCRM.sln`, run `setup.ps1` once, then press F5.

## 2. Project structure

```
AcxiomCRM.sln
src/AcxiomCRM/
  Controllers/          MVC controllers (Dashboard, Customers, Leads, Opportunities, FollowUps, Activities,
                        Users, Roles, AuditLogs, Reports, Account, Home)
  Controllers/Api/      REST API controllers (auth, customers, leads, opportunities, follow-ups, reports)
  Models/               Entities: Customer, Lead, Opportunity, FollowUp, Activity, AuditLog, ApplicationUser, enums
  Data/                 ApplicationDbContext (Identity + CRM), DbInitializer, DemoDataSeeder
  Services/             Business layer: one service per module + scope/authorization, audit, dashboard, reports
  Dtos/                 API/form request models (validation attributes) and response DTOs
  ViewModels/           View models for pages, reports and the dashboard
  Validation/           NotInPast, RequiredIf, ValidEnum attributes (server + client) and shared rules
  Infrastructure/       Paging, CSV export, settings, session validation filter, HTML helpers
  ViewComponents/       Header notifications (overdue / due-today follow-ups)
  Views/                Razor views
  wwwroot/              CSS, JS (site, validation adapters, dashboard charts), bundled libraries
  Migrations/           Generated by the setup script (InitialCreate)
tests/
  acceptance_test.py    HTTP end-to-end acceptance suite (170 checks)
  browser_test.py       Headless-browser checks: client validation, dialogs, charts, layout (21 checks)
docs/API.md             REST API reference
AcxiomCRM.http          Sample API requests
```

Layering follows section 3 of the specification: **Views/Controllers** (presentation) → **Services** (application and
business rules, workflows, authorization scope) → **ApplicationDbContext** (data access via EF Core LINQ only) → SQLite.
Auditing, validation and security are cross-cutting.

## 3. Modules

| Module | What is implemented |
|---|---|
| Authentication | Login, Register, Logout, Change password, Access-denied page. ASP.NET Core Identity (PBKDF2 hashing), password policy, lockout after 5 failed attempts for 15 minutes (configurable), HttpOnly/SameSite=Strict cookies with 30-minute sliding expiry, per-IP login rate limiting. |
| Dashboard | 8 required KPI cards + weighted pipeline, pending/overdue follow-ups. Chart.js: Lead Status, Opportunity Pipeline, Monthly Sales (last 12 months, configurable). Period filter: All time, Today, This Week, This Month, Custom range. Role-specific panels: Admin – users & security stats; Manager/Admin – pipeline by owner; Sales – recent activities. All figures come from records in the user's scope. |
| Customers | Create, view, edit, delete (Admin/Manager; deactivates instead when history exists), search (name, email, phone, company, code), status/owner filter, sort, paging. Auto code `CUST-00001`. Email and phone unique (checked live in the form and enforced on the server and by unique indexes). Details page with opportunities, follow-ups, activities, source leads and change history. |
| Leads | Create, view, edit, delete (Admin/Manager), search/filter by name, company, status, source, priority, assigned user. Statuses New → Contacted → Qualified → Converted, plus Unqualified/Lost, with server-enforced transitions. **Conversion** of a Qualified lead to a new or existing customer and optionally an opportunity, in one transaction, audited. |
| Opportunities | Create, view, edit, delete (Admin/Manager), search/filter by name, customer, stage, status. Stages Qualification, Proposal, Negotiation, Won, Lost; Mark Won/Lost with outcome remarks; weighted amount = Amount × Probability / 100; Sales Pipeline board. Rules: Amount > 0, Probability 0–100, Expected Close Date not in the past while open; closed opportunities are final. |
| Follow-ups | Schedule against exactly one customer, lead or opportunity; Pending/Today/Upcoming/Overdue views; filter by date, status, assigned user, related customer/lead; complete (logs an activity and moves a New lead to Contacted), reschedule, mark missed or cancelled. Date cannot be earlier than today. Header bell shows the user's overdue and due-today items. |
| Activities | Call, Meeting, Email, Task with subject, description, date, status, customer/lead, assigned user; filter by type, date range, status, user. |
| Users & Roles | Admin: create, edit, activate/deactivate, unlock, reset password, assign exactly one role and a reporting manager; search by name/email, role, status (active/inactive/locked). Managers get a read-only view of their team. Roles & Permissions page shows the matrix. Role/status changes end the user's existing sessions immediately. |
| Audit Log | Login, failed login, lockout, logout, register, create, update, status change, delete/deactivate, convert, complete, reschedule, role change, password change/reset, unlock, access denied. Stores user, action, entity, record id, old/new values (changed fields only, never passwords/hashes), result, details, timestamp and IP. Filters by user, module, action, result and date range. Append-only: no edit/delete actions, the DbContext rejects modifications, and SQLite triggers block UPDATE/DELETE. |
| REST API | Customers (GET, GET by id, POST, PUT, DELETE), Leads, Opportunities, Follow-ups (GET, GET by id, POST), Pipeline report, Auth login/logout. DTOs only, validation at the boundary, 200/201/400/401/403/404/409/429, RFC 7807 errors. See `docs/API.md`. |
| Reports | Customer, Lead, Follow-Up, Opportunity, Pipeline (stage-wise + owner-wise + weighted), Conversion (by owner and source; win rate), User Activity (Admin/Manager), Audit (Admin). Every report: date-range and relevant filters, sortable columns, paging, CSV export, print, role-scoped data. |

### Role-based access (enforced on the server)

| | Admin | Manager | Sales Executive |
|---|---|---|---|
| CRM records | All | Own + team members' | Assigned to / created by self |
| Delete customers, leads, opportunities, activities | Yes | Team records | No |
| Assign records to | Any active user | Self or team | Self |
| Users | Full | Team, read-only | No |
| Roles, Audit Log, Audit Report | Yes | No | No |
| User Activity Report | Yes | Team | No |

Scope is applied to every list, lookup, dashboard figure, report and API query; direct access to an out-of-scope record by
URL or API returns 403, and hidden menu items are never the only protection.

## 4. Validation

Both layers use the same attributes on the request models (`Dtos/Requests.cs`), so the browser, the MVC server path and
the API all enforce identical rules. Client-side: jQuery unobtrusive validation plus custom adapters (`wwwroot/js/validation.js`)
for *not in the past* and *required-if*. Server-side: model validation, then the services re-check business rules,
duplicates, workflow transitions, referenced records and record ownership before any database write.

| Rule | Message |
|---|---|
| Opportunity Amount ≤ 0 | Opportunity Amount must be greater than 0. |
| Probability outside 0–100 | Probability must be between 0 and 100. |
| Expected Close Date in the past (open opportunity) | Expected Close Date cannot be in the past. |
| Follow-up date before today | Follow-up date cannot be earlier than today. |
| Invalid email | Enter a valid email address. |
| Invalid phone (project rule: 10-digit Indian mobile starting 6–9) | Enter a valid phone number. |
| Required / length | Field-specific messages, e.g. "Customer Name is required." |
| Duplicate customer email / phone | A customer with this email (phone number) already exists. |
| Invalid / tampered status value | The value '…' is not valid for Lead Status. |

## 5. Configuration

`appsettings.json` (no secrets):

* `ConnectionStrings:DefaultConnection` – SQLite file in `App_Data` (`|DataDirectory|` is resolved at startup).
* `Security` – password policy, lockout threshold/duration, session timeout, login rate limit, API token lifetime.
* `Dashboard` – months shown in Monthly Sales, upcoming follow-up window.
* `Seed` – `SeedDemoData` (true only in `appsettings.Development.json`); passwords come from user-secrets/environment.

Production notes: run with `ASPNETCORE_ENVIRONMENT=Production` behind HTTPS (cookies are then `Secure`-only and HSTS is
on), supply the connection string through environment variables or a secret store, and set `Seed:AdminEmail` /
`Seed:AdminPassword` once to create the first Admin.

## 6. Testing

```bash
pip install requests playwright && playwright install chromium
dotnet run --project src/AcxiomCRM            # in one terminal (Development, demo data)
python tests/acceptance_test.py --base-url http://localhost:5173 --password "Demo@12345"
python tests/browser_test.py   --base-url http://localhost:5173 --password "Demo@12345" --screenshots test-screenshots
```

The acceptance suite walks through every scenario in section 17.19 (anonymous access, register/login, client and
server validation, bypassed requests, opportunity and follow-up rules, Sales Executive/Manager/Admin scope, audit entries,
API JSON, dashboard KPIs and charts) and also covers duplicates, anti-forgery, lockout, password policy, lead workflow and
conversion, follow-up completion/rescheduling, immediate session revocation on role change/deactivation, bearer-token
login/logout, 400/401/403/404/409 responses, report scoping, filters, paging and CSV export. Run it against a freshly
seeded database (delete `App_Data/acxiomcrm.db` first) for predictable results.

### How this build was verified

The application was developed in an environment without access to the NuGet package feed, so the EF Core and
Identity-EF packages could not be restored there. To verify it anyway, the complete application source – every
controller, service and Razor view – was compiled with zero warnings and run against a small in-memory stand-in for the
EF Core/Identity-EF APIs it uses, with the real ASP.NET Core framework (Identity, authentication, authorization,
anti-forgery, MVC, rate limiting) underneath. Against that build, **170/170 acceptance checks** and **21/21 browser
checks** passed.

What that does **not** cover is EF Core's translation of the LINQ queries to SQLite SQL and the generated migration. The
queries deliberately use only well-supported constructs (filtering, sorting, paging, `Contains`, `GroupBy` counts, and
in-memory aggregation of money values because SQLite cannot sum decimals). Please run `setup.ps1`, start the app and
run `tests/acceptance_test.py` once on your machine – that confirms the database layer end to end.

## 7. Known limitations / interpretation notes

* "Team" is defined by the reporting-manager field on each Sales Executive (set on the user form).
* Sales Executives can create and edit their records but not delete them; deletion is limited to Admin and Manager
  (least privilege). Customers with history are deactivated rather than deleted to keep the audit trail intact.
* Each user has exactly one primary role (the three roles are fixed; no custom roles).
* Dates and times use the server's local time. Overdue = a Planned follow-up whose date is before today.
* The Monthly Sales chart covers the configured reporting period (last 12 months by default), independent of the
  dashboard period filter; KPI counts use created date, Won/Lost counts use the date the opportunity was closed.
* API bearer tokens are ASP.NET Core Identity bearer tokens (not JWT); `POST /api/auth/logout` revokes all of the
  user's tokens and sessions.
* Password-reset is administrator-driven (Admin sets a new password that must meet the policy); there is no
  email-based self-service reset because the specification does not include an email service.
* .NET 8 is an LTS release supported until November 2026; moving to .NET 10 later only requires changing the target
  framework and package versions.
